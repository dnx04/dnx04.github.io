Writeup for Cat - a HackTheBox medium lab.

Enumeration

The webserver is running Apache 2 and its web source code git repository is exposed. We can reconstruct the source code using git-dumper.

Get the user flag

In short, the website allows us to fill in a form and upload a cat image so that an admin can review it. This scenario leads us to explore Session Hijacking using XSS.

Stored XSS: Register (source) → View (sink)

Let’s take a closer look in the source code. In the register function, we can see that the username we register is stored in the database without any sanitization, and directly assigned to _SESSION['username'].

This variable is used as-is in contest.php to show the username uploaded the cat image.

And in view_cat.php, we know that this username will be fetched whenever an admin reviews the form.

Stored XSS: Exploitation

Let’s craft a XSS payload that sends us the admin’s cookie whenever the admin bot review our payload.

Register using the payload as the username, and fill in the form as normal. Then we will receive the PHPSESSID of the admin in base64.

SQLi: catName

The admin can view, accept or reject a cat image. Inspecting the accept function (accept_cat.php), we see that the parameter catName is directly embedded into the SQL query.

Privilege Escalation to Root

You can just linpeas.sh to get all of these information at once.

Let’s list the running services using netstat.

There is a Gitea service running at port 3000, let’s forward it to our pwnbox. The Gitea’s version is 1.22.0, vulnerable to Gitea 1.22.0 - Stored XSS - Multiple webapps Exploit. This CVE exploits Stored XSS on the description field of a Gitea repo.

As there are multiple users running on this system, let’s check if there are internal mails transfered between local users. Yes there is.

Everything starts to click. Jobert will check any email send to him and click on a Gitea repo link. Also, there is an admin’s repo Employee-management explicitly stated in the email. So let’s craft an XSS payload that send us arbitrary content in this repo. We will read index.php.

Put this payload in the description of the repo, and send an email to jobert .So fast we got the content of this file in base64 which contains the admin password.

So we got root credentials: root:IKw75eR0MR7CMIxhH0. And we’re done.
