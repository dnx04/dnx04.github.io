Heal - HackTheBox

Published: Jun 3, 2025 Updated: Oct 18, 2026 Reading time: 3 min read Length: 297 words

Category: Challenger Tags: ctf / hackthebox / cybersecurity

Enumeration

nmap shows that SSH and HTTP are available.

The website is a portfolio generating service. We can access its API subdomain and it is written in Ruby on Rails.

Also, there is a subdomain take-survey.heal.htb hosted using LimeSurvey.

There is a high chance that this LimeSurvey is vulnerable to a CVE, but we must first get an admin credential.

LFI → Credential leak

Testing the input forms, some of them are vulnerable to server-side XSS, but it got little use here.

The service allows downloading one’s generated CV.

By tampering HTTP verb and LFI, we can read files on the webserver (also we need to insert our auth token). There are 2 users on the system, ralph and ron.

So we can read the config files of Ruby on Rails webserver. Let’s target config/database.yml. There we got 2 sqlite3 databases, test and development . Let’s clone the development.sqlite3 database.

Good, now cracking the hash digests then we got ralph:147258369.

LimeSurvey RCE → User flag

LimeSurvey 6.6.4 is vulnerable to a RCE using webshell upload in plugin installation. We will use this POC: Y1LD1R1M-1337/Limesurvey-RCE: LimeSurvey Authenticated RCE. Something to note here:

  1. Change config.xml so that our plugin is compatible with LimeSurvey 6.

  2. Change ip and port accordingly in php-rev.php.

Then we got our reverse shell.

Let’s continue investigate LimeSurvey config. We found a password.

This password is for ron, and we got the user flag.

Slam a RCE → Root flag

Let’s see the local services available.

Port 8500 is reserved for HashiCorp Consul service and is running in root privileges. Let’s forward it back to our pwnbox.

Consul v1.19.2 is vulnerable to a RCE: Hashicorp Consul v1.0 - Remote Command Execution (RCE) - Multiple remote Exploit. So just slam it and we got the root flag.
